## 二、关键结论

### 1. 现有系统结构（演示所见）
- **门户**：统一入口，待办提醒 + 应用集成（OA、业务系统、邮箱、访客等各子系统均为不同时期拼凑开发，风格不一，部分供应商已倒闭）。
- **OA 协同办公**：流程审批（合同/采购/用章/差旅/请假/IT 权限）、行政文件制度库。
- **业务管理流程系统（bizSys，本次核心）**：基础信息（客户/CRM）→ 合同 → 任务 → 实验室执行 → 报告 → 结算开票到账，外加样品管理。
- **周边**：质量管理体系流程、保密数据传输、企业邮箱、财务系统、独立的样品/仓库管理系统（安吉，打开极慢、抱怨多）。

### 2. 业务主流程（MVP 核心链路）
```
维护客户 → 新建/审批合同（上传附件、逐级审批）→ 按合同新建任务（1 合同 → N 任务）
→ 任务分配业务板块/实验室 → 添加样品（自动生成编号、VIN、在库状态、入出库）
→ 实验执行 → 上传报告 → 审批 → 自动转 PDF → 盖签章 → 任务结束
→ 结算（申请开票 → 财务生成发票 → 到账登记关联任务）→ 闭环
```
关联关系：**合同 1—N 任务，任务 1—N 任务（一任务只挂一合同，多合同则再建任务），任务 1—N 样品**。

### 3. 需求方明确的范围取舍
| 要做（第一期/MVP） | 不做/暂缓 |
|---|---|
| 客户维护（CRM 基础信息）、合同管理、任务管理（含分配/编号规则）、样品管理（简化版入出库）、报告流程（上传-审批-PDF-签章）、财务结算（开票/到账，先人工）、组织架构与账号（基础数据）、全界面 Excel 导入导出、保密文档分享（链接+密码，12 月可能要用）、邮箱接口关联 | 设备管理、统计分析、独立的样品/仓库系统（重做简化）、访客系统、现有 OA 的复杂流程拼装（结构从简）、企业微信工作流（先保留，后续整合） |

### 4. 非功能性与集成要求
- **速度是全部系统的最核心要求**（"一定要快"，现有系统卡顿被反复吐槽）。
- 任务类型可自定义，当前 3 类：工程咨询、模型加工中心、风洞实验。
- 工作流审批：目前在企业微信，长期要收编进新系统并与业务系统关联。
- 与 **WTCS** 集成：业务系统的测试/风洞任务推送到 WTCS。
- 财务到账识别方式待与财务确认；先做人工录入，后续视接口对接。
- 登录：账号密码 + 企业微信扫码。
